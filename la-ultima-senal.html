Un mini libro interactivo para aprender JavaScript desde cero.

12 capítulos · Una sola aventura · Tu laboratorio: la consola de Chrome

Antes de despegar

No necesitas experiencia, instalaciones ni un editor. Necesitas Chrome en un computador, una pestaña vacía y ganas de comprobar qué pasa cuando cambias una instrucción.

Has aterrizado de emergencia en Nébula. La estación está a oscuras. Tu compañero, el robot LUMA, puede leer órdenes, pero sus controles han desaparecido. Tres balizas deben volver a funcionar para pedir rescate. Cada herramienta de JavaScript que descubras permitirá reconstruir una parte de ese sistema.

Trabaja con este libro abierto y otra pestaña para el laboratorio. En la barra de direcciones de esa segunda pestaña escribe about:blank y pulsa Enter. No practiques en bancos, redes sociales, tiendas ni cuentas personales. Tampoco ejecutes las misiones en la consola de este libro: necesitarás conservar su navegación.

Cómo recorrer esta aventura

  1. Lee el problema y haz una predicción antes de ejecutar.
  2. Escribe el fragmento en tu laboratorio. Observa el resultado.
  3. Cambia algo. Comprueba si tu predicción se mantiene.
  4. Intenta el desafío. Abre primero la pista y después, si la necesitas, la solución.
  5. Completa el punto de control antes de avanzar.

Las soluciones son posibles, no únicas. Si tu versión cumple las reglas y puedes explicar por qué, también cuenta.

Cada capítulo está pensado para 15–30 minutos. Si terminas pronto, prueba los tres niveles y la misión extra. Haz pausas: el objetivo es poder explicar tus decisiones, no llegar al final deprisa.

Tres etiquetas para no perder el rumbo

  • Ruta: fragmento que se incorpora al proyecto; ejecútalo en orden.
  • Prueba: experimento temporal o repetible. Lee si modifica el estado.
  • Reemplaza: nueva versión de una función anterior; escribe la definición completa y ejecútala.

Los errores deliberados están marcados como BUG. No forman parte de la versión correcta. Los desafíos no añaden requisitos secretos a capítulos posteriores: el punto de control indica el estado necesario.

Tu partida vive en esta pestaña

Al recargar o cerrar la pestaña del laboratorio se pierde el programa y su estado. Borrar los mensajes de la consola no borra las variables. Repetir una declaración con let o const puede producir un error de nombre ya declarado. Si el nombre ya existe, cambia su valor con una asignación, sin repetir let.

El apéndice «Recuperar el laboratorio» permite reconstruir lo necesario si interrumpes la aventura. No lo necesitas para empezar. El progreso de lectura que marcas en este libro es independiente del estado del juego.

Capítulo 1 — ¿Hay alguien ahí?

Tiempo orientativo: 15 minutos · Objetivo: establecer contacto.

La historia

La luz de emergencia parpadea. Un robot despierta junto a ti.

—Soy LUMA. Si puedes escribir una orden, todavía podemos salir de aquí.

La pantalla muestra un espacio vacío. Esa será nuestra consola: nuestro laboratorio de JavaScript.

Tu misión: una respuesta en los primeros cinco minutos

En la pestaña about:blank, abre la consola:

  • Windows/Linux: Ctrl + Shift + J.
  • Mac: Cmd + Option + J.
  • Alternativa: clic derecho en la página → Inspeccionar → pestaña Console/Consola.

Haz clic junto al símbolo > o en el campo de entrada. Escribe la primera orden a mano:

Antes de pulsar Enter…

¿Crees que la consola mostrará la orden completa o solo el mensaje entre comillas?

Experimenta · Ruta

console.log("LUMA, ¿me recibes?");

Pulsa Enter. Deberías ver LUMA, ¿me recibes?. Ya has dado una instrucción al computador.

Puede aparecer undefined debajo. Es el resultado que devuelve esta llamada, no un error. Lo investigaremos cuando el juego necesite distinguir diferentes ausencias.

Lo que acabas de descubrir

console.log() muestra información. El mensaje va entre paréntesis. Las comillas indican que ese contenido es texto: un string.

Las comillas rectas " o ' sirven; las comillas decorativas “ ” no. El punto y coma cierra la instrucción en los ejemplos de este libro.

Ahora tú · Nivel 1: modifica

Cambia el mensaje para que LUMA responda. Esta llamada se puede repetir sin cambiar la partida:

console.log("LUMA: señal recibida. Busquemos las balizas.");

Tu primera victoria ya está completa: dos personajes se comunican mediante instrucciones que tú escribiste.

Nivel 2: construye

Escribe dos llamadas nuevas: una debe describir dónde estás; otra debe decir qué necesitas. Usa el mismo mecanismo, con tus propios textos.

BUG detectado: el mensaje roto

Prueba deliberadamente incorrecta. Antes de ejecutarla, busca lo que falta:

console.log("LUMA, enciende la luz);

La consola mostrará un SyntaxError. El texto exacto puede variar. La pista está en cómo está escrita la instrucción: falta cerrar las comillas.

Corrige y ejecuta:

console.log("LUMA, enciende la luz");

Un error es información sobre una instrucción que el sistema no pudo completar. Aquí no has estropeado nada.

Nivel 3: desafío — Tu primer registro

Sin copiar el ejemplo, haz que aparezcan tres mensajes: tu identificación, el problema de la estación y tu objetivo. Intenta resolverlo antes de abrir las ayudas.

Pista

Cada mensaje puede salir con una llamada independiente. Comprueba las parejas de comillas y paréntesis.

Solución posible — abrir después de intentarlo 
console.log("Soy la persona a cargo del rescate.");
console.log("Las comunicaciones están apagadas.");
console.log("Voy a reparar tres balizas.");

Son tres instrucciones del mismo tipo. Tus textos pueden ser distintos.

Chrome también puede hablar

Puedes encontrar advertencias o mensajes ajenos a lo que acabas de escribir. Si Chrome bloquea el pegado y muestra una advertencia, léela y escribe estos fragmentos breves a mano; no necesitas desactivar esa protección. Solo ejecuta código del curso que entiendas. No pegues código desconocido de Internet.

Si no ves la salida, comprueba que estás en Console, que ejecutaste con Enter y que los filtros permiten mostrar mensajes. No escribas el símbolo >: ya lo pone la consola.

Misión completada

Funcionando: comunicación con LUMA. Logro: primer contacto.

Tu arsenal: console.log(), strings, lectura inicial de un SyntaxError.

Punto de control: todavía no hay variables ni recursos que restaurar.

Continuará… LUMA conoce la ruta, pero ha olvidado quién eres y cuánta energía queda.

Capítulo 2 — Lo que la nave recuerda

Tiempo orientativo: 15–20 minutos · Objetivo: crear la memoria del juego.

La historia

—Puedo mostrar mensajes —dice LUMA—, pero necesito recordar los datos de esta misión.

Si escribes «100 de energía» en un mensaje, solo muestras palabras. Necesitamos un valor que otras instrucciones puedan consultar y cambiar.

Antes de pulsar Enter…

Si guardamos tu nombre, ¿podremos mostrarlo después sin volver a escribir el texto completo?

Experimenta · Ruta: declara una sola vez

let nombre = "Alex";
let energia = 100;
const estacion = "Nébula";
let senalEnviada = false;

Puedes elegir otro nombre. El resto debe empezar como aparece aquí.

Ahora consulta la memoria:

console.log(nombre);
console.log(energia);
console.log(estacion);
console.log(senalEnviada);

¿Qué ocurrió?

nombre está asociado a un texto. energia tiene un número. senalEnviada tiene false: la señal todavía no se ha enviado.

Una variable es un nombre asociado a un valor. Al principio puedes imaginar una caja etiquetada. Lo importante es que JavaScript usa ese nombre para acceder a un valor; no es una caja física y más adelante verás valores que representan colecciones.

let permite asignar un valor nuevo. const impide reasignar ese nombre: la estación seguirá siendo Nébula. Un booleano solo tiene dos valores: true y false. Escribimos ambos sin comillas.

Nivel 1: modifica

Predice cuál será el nombre después de estas dos instrucciones. Ejecútalas y luego vuelve a elegir el tuyo:

nombre = "Iris";
console.log(nombre);

No repetimos let: la variable ya existe.

nombre = "Alex";

Puedes reemplazar Alex por tu nombre. Esta elección no cambia las reglas.

Nivel 2: construye

LUMA necesita recordar su nombre. Declara const robot = "LUMA"; y muéstralo. Será una etiqueta fija de nuestro compañero.

Ruta: asegura este dato antes de avanzar

Si ya resolviste el nivel 2, no vuelvas a ejecutar esta declaración:

const robot = "LUMA";

BUG detectado: una letra perdida

¿Qué ocurrirá al escribir esto?

console.log(energa);

Un ReferenceError señala que el nombre usado no existe en este contexto. Compara energa con energia. JavaScript también distingue mayúsculas: Energia y energia son nombres diferentes.

Nivel 3: desafío — La prueba de memoria

Cambia temporalmente la energía a 80, consulta su valor y devuélvela a 100. Haz que el informe final muestre también si la señal está enviada.

Pista

Los datos ya están declarados. Para cambiarlos, utiliza su nombre, = y el valor nuevo. Para consultarlos, usa la herramienta del capítulo 1.

Solución posible 
energia = 80;
console.log(energia);
energia = 100;
console.log(energia);
console.log(senalEnviada);

Primero actualizas, después consultas. Restauras 100 para que el siguiente capítulo empiece con una partida conocida.

Un dato que no puede reasignarse

Prueba incorrecta opcional: estacion = "Otro planeta"; produce un TypeError porque intentas reasignar una constante. La asignación falla y estacion conserva su valor.

No hace falta memorizar los nombres de todos los errores. Empieza por preguntar: ¿la instrucción está mal escrita, el nombre no existe o estoy intentando una operación no permitida?

Misión completada

Funcionando: memoria de la partida. Logro: identidad recuperada.

Tu arsenal: valores, números, booleanos, variables, let, const y asignación.

Punto de control · Ruta:

energia = 100;
senalEnviada = false;
console.log(energia, senalEnviada);

Debes ver 100 false. nombre conserva tu elección; estacion y robot ya existen.

Continuará… La compuerta se abre, pero el medidor de energía empieza a bajar.

Capítulo 3 — Cada paso tiene un coste

Tiempo orientativo: 15–20 minutos · Objetivo: hacer que las acciones cambien un recurso.

La historia

Explorar un sector cuesta 10 puntos de energía. Reparar su baliza costará otros 15. LUMA necesita calcular esos cambios, no fingirlos en un mensaje.

Antes de pulsar Enter…

Partimos de 100. ¿Qué valor tendrá energia después de descontar 10? ¿Y si ejecutas la misma orden dos veces?

Experimenta · Ruta

energia = energia - 10;
console.log(energia);

Deberías ver 90. Primero se calcula lo que está a la derecha del =; después se asigna el resultado a energia. Repetirlo volvería a descontar 10.

Haz que el informe hable · Ruta

console.log(`${nombre}, quedan ${energia} puntos en ${estacion}.`);

Los símbolos que rodean el texto son acentos graves o backticks: `. No son comillas simples. Este texto es un template literal. Cada ${...} inserta el valor de una expresión.

Nivel 1: modifica

Prueba un descuento de 5. Observa el informe. Como aún no hemos explorado de verdad, restaura después el recurso:

energia = energia - 5;
console.log(`Energía de prueba: ${energia}`);
energia = 100;

Nivel 2: construye

Muestra el coste total de explorar y reparar un sector. Después calcula el de tres sectores. No cambies energia en este cálculo.

Experimenta · Prueba sin efectos

console.log(10 + 15);
console.log((10 + 15) * 3);
console.log(100 - (10 + 15) * 3);

Los resultados son 25, 75 y 25. Los paréntesis agrupan el coste de un sector. + suma, - resta, * multiplica y / divide números.

BUG detectado: una suma que pega textos

Predice ambos resultados:

console.log("10" + 5);
console.log(10 + 5);

Verás 105 como texto y 15 como número. Con un texto en esta expresión, + une contenidos. Por eso la energía se guarda como 100, sin comillas. Usaremos números para los costes y template literals para los informes.

Nivel 3: desafío — El presupuesto del rescate

Muestra una frase que diga cuánto queda después de explorar y reparar las tres balizas, partiendo de tu energía actual de 100. Haz el cálculo dentro del mensaje, sin gastar realmente energía.

Pista

Dentro de ${...} también puede ir un cálculo. El coste total es el coste de un sector multiplicado por tres.

Solución posible 
console.log(`Después del rescate quedarían ${energia - (10 + 15) * 3} puntos.`);

La expresión produce 25. Como no asignas un valor a energia, la partida sigue teniendo 100.

Misión completada

Funcionando: cálculo de costes e informe con datos actuales. Logro: presupuesto de rescate.

Tu arsenal: operadores aritméticos, expresiones, asignación y template literals.

Punto de control · Ruta:

energia = 100;
console.log(`Reserva: ${energia}`);

Continuará… ¿Qué debe hacer la compuerta cuando alguien intenta gastar más energía de la que tiene?

Capítulo 4 — La puerta que dice no

Tiempo orientativo: 20–25 minutos · Objetivo: impedir acciones inválidas.

La historia

Una compuerta necesita 10 puntos para abrirse. El sistema antiguo descontaba energía incluso cuando no había suficiente. Vas a reparar esa regla.

Antes de pulsar Enter…

¿Qué significa «tener suficiente»? ¿Debería permitir la acción con exactamente 10 puntos?

Experimenta · Ruta

console.log(energia >= 10);
console.log(energia === 0);

Con energía 100 obtendrás true y false. Una comparación produce un booleano. >= significa «mayor o igual». === compara sin convertir automáticamente los tipos. = asigna: no son intercambiables.

Ruta: la decisión

if (energia >= 10) {
  console.log("La compuerta permite avanzar.");
} else {
  console.log("No hay energía suficiente.");
}

Lee el bloque como una frase: si hay suficiente energía, muestra el primer mensaje; si no, muestra el segundo. Las llaves agrupan instrucciones.

Para escribir varias líneas a mano, usa Shift + Enter entre líneas. Ejecuta con Enter cuando el bloque esté completo y todas las llaves estén cerradas. No ejecutes cada línea de un bloque incompleto por separado.

Un diagnóstico con tres respuestas

Prueba: escribe el bloque completo antes de ejecutarlo.

if (energia === 0) {
  console.log("Sin energía.");
} else if (energia < 25) {
  console.log("Reserva baja.");
} else {
  console.log("Reserva suficiente.");
}

else if ofrece otra condición cuando la anterior no se cumplió. Solo se ejecuta una de estas ramas.

Nivel 1: modifica

Asigna temporalmente 0, 20 y 100 a energia; repite el diagnóstico para cada valor. Predice el mensaje antes de ejecutarlo. Termina con 100.

Nivel 2: construye

Una puerta exige energía suficiente y que la misión siga activa. Para nuestra partida, activa significa que la señal todavía no se ha enviado:

console.log(energia >= 10 && !senalEnviada);

&& exige ambas condiciones. ! invierte el booleano: !false es true. || permite que se cumpla una condición o la otra. Por ejemplo, energia === 0 || senalEnviada detecta dos motivos diferentes para detener una acción.

BUG detectado: la frontera equivocada

Alguien propone energia > 10 para abrir la compuerta. Prueba con energía 10. ¿La puerta debería abrirse? La comparación estricta la bloquearía. El código puede ejecutarse sin errores y aun así expresar una regla incorrecta: es un error de lógica.

Nivel 3: desafío — Gasta solo si puedes

Escribe una decisión que descuente 10 únicamente cuando hay energía suficiente y la señal no se ha enviado. Si no se permite, muestra una explicación y conserva la energía.

Pista

La resta debe estar dentro de la rama permitida. Comprueba dos condiciones antes de cambiar el recurso.

Solución posible 
if (energia >= 10 && !senalEnviada) {
  energia = energia - 10;
  console.log(`Acción permitida. Quedan ${energia}.`);
} else {
  console.log("Acción bloqueada: revisa energía y señal.");
}

Solo la primera rama modifica la energía. Con 100 y señal sin enviar, queda 90. Con 5, sigue habiendo 5.

Misión de memoria

Sin añadir una herramienta nueva, muestra un informe con tu nombre y el valor de energía después de probar la puerta. ¿Cómo puedes consultar el resultado sin cambiarlo?

Misión completada

Funcionando: bloqueo de acciones sin recursos. Logro: compuerta segura.

Tu arsenal: comparaciones, decisiones, operadores lógicos y errores de lógica.

Punto de control · Ruta:

energia = 100;
senalEnviada = false;

Continuará… Detrás de la puerta hay un registro de Iris. La palabra de acceso tiene espacios y mayúsculas inesperadas.

Capítulo 5 — Un mensaje escrito a medias

Tiempo orientativo: 15–20 minutos · Objetivo: interpretar una respuesta escrita.

La historia

Un terminal acepta la palabra rescate. Sin embargo, alguien la escribió como RESCATE. LUMA la rechaza. Las personas pueden escribir la misma intención de formas diferentes: debemos preparar el texto antes de compararlo.

Antes de pulsar Enter…

¿Los espacios y las mayúsculas harán que los dos textos sean distintos?

Experimenta · Ruta

let respuesta = " RESCATE ";
console.log(respuesta === "rescate");

Obtendrás false. Vamos a limpiar el dato:

respuesta = respuesta.trim();
respuesta = respuesta.toLowerCase();
console.log(respuesta === "rescate");

Ahora verás true.

Lo que acabas de descubrir

Un método es una función que usamos a través de un valor u objeto, con un punto y su nombre. trim() devuelve el texto sin espacios en los extremos. toLowerCase() devuelve una versión en minúsculas.

Estos métodos no cambian el string original. Aquí actualizamos respuesta porque asignamos el texto que devuelven. trim() no elimina espacios en medio de una frase.

La pista de Iris · Ruta

const primerRegistro = "Iris: apagamos la señal para proteger la estación.";
console.log(primerRegistro.includes("proteger"));

includes() comprueba si un texto contiene otro; devuelve true o false. También distingue mayúsculas. Que una frase contenga una palabra no significa que sea exactamente esa palabra.

Nivel 1: modifica

Asigna " ResCate " a respuesta, repite la limpieza y comprueba el resultado. Después prueba "res cate". ¿Por qué este segundo texto no coincide?

Nivel 2: construye

Escribe una decisión que muestre «Registro desbloqueado» cuando la respuesta limpia sea exactamente rescate, y un mensaje de reintento en otro caso.

Nivel 3: desafío — Una contraseña demasiado permisiva

Una versión usa respuesta.includes("rescate") para abrir el registro. Eso acepta "no quiero rescate". Corrígela para aceptar únicamente la palabra de acceso, ignorando espacios exteriores y mayúsculas.

Pista

Primero prepara el texto; después decide si necesitas buscar una parte o comparar el contenido completo.

Solución posible 
respuesta = respuesta.trim().toLowerCase();
if (respuesta === "rescate") {
  console.log("Registro desbloqueado.");
} else {
  console.log("Prueba otra vez.");
}

Se pueden encadenar métodos: trim() entrega el texto al siguiente método. La comparación completa impide aceptar una frase que solo contiene la palabra.

BUG detectado: un método que nunca se ejecutó

Compara respuesta.trim con respuesta.trim(). Sin paréntesis haces referencia al método; con paréntesis lo llamas. En este juego necesitamos el texto que resulta de ejecutarlo.

Misión completada

Funcionando: respuesta escrita tolerante a espacios exteriores y mayúsculas. Logro: primer registro recuperado.

Tu arsenal: métodos, limpieza de strings, búsqueda y comparación exacta.

Punto de control: energía 100 y señal false. Estos experimentos no gastan recursos.

Continuará… Iris apagó la señal para proteger algo. LUMA necesita órdenes reutilizables para investigar.

Capítulo 6 — LUMA aprende una orden

Tiempo orientativo: 20–25 minutos · Objetivo: reunir instrucciones que puedas reutilizar.

La historia

Cada revisión exige volver a escribir el informe y cada puerta repite la misma comprobación. LUMA propone guardar esas tareas con un nombre.

Antes de pulsar Enter…

Si enseñamos una orden, ¿se ejecutará al definirla o cuando la llamemos?

Experimenta · Ruta

function verEstado() {
  console.log(`${nombre} en ${estacion}`);
  console.log(`Energía: ${energia}`);
  console.log(`Señal enviada: ${senalEnviada}`);
}

Esta definición prepara la tarea; todavía no muestra el informe. Ahora llama a la función:

verEstado();

Lo que acabas de descubrir

Una función reúne instrucciones para ejecutarlas cuando la llamas. Los paréntesis de la llamada activan la tarea. Si después cambia energia, la próxima llamada consultará su valor actual.

Una orden que recibe información · Ruta

function puedePagar(coste) {
  return coste >= 0 && energia >= coste;
}

coste es un parámetro: un nombre para el dato que recibe la función. return entrega un resultado y termina esa llamada.

Predice el resultado antes de ejecutar:

console.log(puedePagar(10));
console.log(puedePagar(150));
console.log(puedePagar(-5));

Con energía 100: true, false, false. Esta función comprueba; no gasta. Un coste negativo tampoco es válido.

Mostrar y devolver son tareas distintas

verEstado() muestra información y no tiene un return explícito: devuelve undefined. puedePagar(10) devuelve un booleano que otra instrucción puede usar. Dentro de una función, console.log(true) por sí solo no equivale a return true.

LUMA también necesita emitir mensajes que podamos reutilizar después en el panel visual:

function avisar(mensaje) {
  console.log(mensaje);
  return mensaje;
}

Esta función hace las dos cosas: muestra el mensaje y lo devuelve. En la consola puede aparecer el texto como salida y también como resultado de la llamada; no significa que la acción se haya ejecutado dos veces.

Nivel 1: modifica

Cambia temporalmente energia a 5. Predice puedePagar(10), ejecuta y restaura 100.

Nivel 2: construye

Construye costeSector() para devolver el coste de explorar y reparar un sector: 10 más 15. No modifiques la energía. La función es una herramienta de cálculo opcional.

BUG detectado: un nombre que vive dentro

Prueba por separado:

function probarSensor() {
  const lectura = "estable";
  return lectura;
}
console.log(probarSensor());

Después ejecuta esta instrucción incorrecta:

console.log(lectura);

Produce un ReferenceError. lectura existe dentro de la función. Ese alcance se llama scope. Las variables declaradas con let y const dentro de un bloque también se limitan a ese bloque. El parámetro coste no existe fuera de su función.

Nivel 3: desafío — Una respuesta reutilizable

Crea mensajeReserva(coste) para devolver «Puedes continuar» si alcanza la energía, o «Necesitas más energía» en otro caso. Aprovecha algo que ya programaste.

Pista

Puedes llamar a una función dentro de otra. Para obtener un texto que otra instrucción utilice, necesitas devolverlo.

Solución posible 
function mensajeReserva(coste) {
  if (puedePagar(coste)) {
    return "Puedes continuar";
  }
  return "Necesitas más energía";
}

El primer return termina la llamada si la condición se cumple. Por eso no hace falta else para el segundo caso. Prueba console.log(mensajeReserva(10)); y cambia el coste.

Misión completada

Funcionando: consultas y comprobaciones reutilizables. Logro: órdenes de LUMA.

Tu arsenal: funciones, llamadas, parámetros, return, scope y salida anticipada.

Punto de control · Ruta:

energia = 100;
verEstado();

Deben existir verEstado, puedePagar y avisar. Las funciones de desafíos son opcionales.

Continuará… Encuentras varias piezas. Un único nombre no basta para recordar toda la mochila.

Capítulo 7 — La mochila de repuestos

Tiempo orientativo: 20–25 minutos · Objetivo: recoger y consumir componentes.

La historia

Las balizas necesitan un cable, un fusible y una batería. Antes de visitar los sectores, vamos a probar la mochila con piezas de entrenamiento.

Antes de pulsar Enter…

¿Cómo guardarías varios componentes juntos? ¿Qué debería pasar cuando utilizas uno?

Experimenta · Ruta

const inventario = [];
inventario.push("cable");
inventario.push("fusible");
console.log(inventario);

Un array es una colección ordenada. [] crea uno vacío. push() añade al final y modifica el array. La consola puede mostrarlo como una lista desplegable.

function actualizarPanel() {

Nivel 2: construye — Un botón que activa una orden

Una función recibirá un texto y otra función: lo que debe suceder al hacer clic.

Reúne los dos tramos antes de ejecutar.

function crearBoton(texto, accion) {
  const boton = document.createElement("button");
  boton.textContent = texto;
  boton.style.margin = "6px";

  boton.style.padding = "10px";
  boton.addEventListener("click", accion);
  document.body.appendChild(boton);
  return boton;
}

addEventListener() registra una función que el navegador llamará cuando ocurra el evento indicado. "click" corresponde al clic o a la activación del botón mediante teclado.

Antes de ejecutar…

¿Esta instrucción explora ahora, o prepara algo para cuando pulses el botón?

Prepara el botón. La función entregada como argumento se ejecuta después, al hacer clic. Si pasáramos explorar(0) directamente, ejecutaríamos la exploración en ese momento y entregaríamos su resultado en lugar de la función que debe atender el clic.

function explorar(indice) {
  if (!sectorValido(indice)) return avisar("Ese sector no existe.");
  if (senalEnviada) return avisar("La misión ya terminó.");
  const sector = sectores[indice];
  if (sector.explorado) return avisar(`Ya exploraste ${sector.nombre}.`);

function reparar(indice) {
  if (!sectorValido(indice)) return avisar("Ese sector no existe.");
  if (senalEnviada) return avisar("La misión ya terminó.");
  const sector = sectores[indice];
  if (!sector.explorado) return avisar("Primero explora este sector.");
  if (sector.reparada) return avisar("Esta baliza ya está reparada.");

  if (!usarPieza(sector.pieza)) return avisar(`Falta la pieza: ${sector.pieza}.`);

let mensajeFinal = null;

function transmitir(mensaje) {
  if (senalEnviada) return avisar("La señal ya fue enviada.");
  if (pendientes().length > 0) return avisar("Todavía hay balizas pendientes.");
  if (mensaje !== "rescate" && mensaje !== "informe") return avisar("Elige rescate o informe.");
  senalEnviada = true;
  mensajeFinal = mensaje;
  if (mensaje === "informe") return avisar("Informe enviado. La historia de Iris está a salvo. Rescate en camino.");
  return avisar("Petición enviada. Una nave de rescate responde.");
}

function reiniciar() {
  energia = 100;
  senalEnviada = false;
  mensajeFinal = null;
  inventario.length = 0;
  for (let indice = 0; indice < sectores.length; indice = indice + 1) {
    sectores[indice].explorado = false;
    sectores[indice].reparada = false;
    sectores[indice].registro = null;
  }
  return avisar("Nueva partida. LUMA vuelve a encenderse.");
}
